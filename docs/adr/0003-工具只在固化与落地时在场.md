# 工具只在固化与落地时在场，初始化之后退场

Workspore 是双向 CLI：save 把调校好的工作区固化成模板，create 从模板落出新工作区（并留一行出身记录）。初始化之后工具退场——不做实例更新跟踪、不做冲突合并、不做首跑引导。理由：工作区里坐着 agent，更新、合并、引导是语义活，agent 天然会干，工具去做是越位。分工就一条：工具管字节（固化、落地），agent 管语义（整理、合并、引导）。

**Considered Options**: Copier 式实例管理（answers 文件记录出处与参数、update 命令做三方合并、冲突裁决 UX）——被否：为一等承诺投入整块产品机制，换来的功能 agent 免费自带；产品复杂度翻倍，与「CLI 只是载体」的定位相悖。

**Consequences**: 产品定义故事 3 相应改写——改进传播的承诺落在未来实例上，旧实例跟上新版本是 agent 的活，不是产品功能；出身记录（create 时写入的一行模板地址 + 版本）是 agent 未来自主更新的唯一原料，故必须写入。
