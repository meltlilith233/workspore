# 「AI Agent 工作区打包复用」开源项目可行性调研

- 调研日期：2026-09-16
- 想法：做一个双向 CLI 开源项目——`save` 把当前 AI agent 工作区（AGENTS.md、skills、MCP 声明、hooks 等）脱敏打包成可分享格式，`create` 从包或 Git 仓库形式的预设一键还原新工作区，并支持「Git 仓库即预设」的分发生态，让工作区开箱即用。
- 已对齐的产品决策（调研前提）：双向 CLI；打包内容含脱敏工具配置（MCP 声明去密钥、hooks、命令定义）；预设分发走 Git 仓库即预设（零后端）。
- 本报告由三路并行调研汇总：竞品全景、痛点与需求验证、技术可行性。除特别标注外，来源核实时间均为 2026-09-16。

---

## 结论（TL;DR）

1. **市场空白基本成立，但窗口正在收窄**。截至 2026-09-16，未检索到与「save 当前工作区 → 脱敏打包 → create 一键还原（跨工具、支持 Git 预设）」完全对位的通用工具；但周边赛道高度拥挤，多个项目从不同方向逼近。
2. **痛点真实且量级不小**。claude-code 仓库「支持 AGENTS.md」issue 拿到 5,153 个 👍；组件级安装器 claude-code-templates 拿到 30.7k stars；大量用户用 symlink、dotfiles、自制脚本土法解决——都在为同一个痛点付费。
3. **技术上可行**。六款主流工具（ZCode、Claude Code、Codex CLI、Cursor、Gemini CLI、OpenCode）的配置面高度同构：纯文件为主 + 每家 1~2 个 JSON/TOML 合并点 + 少数凭证文件。难度分布：纯文件复制（易）、配置合并（中）、脱敏（难）。
4. **最大风险不在技术，在冷启动**。HN 上纯工具型「配置管理」Show HN 普遍只有 3~10 分；而被验证爆火的全是「内容生态 + 工具」组合（claude-code-templates 30.7k、karpathy-skills 213k★，后者数据待复核）。若做，预设内容生态必须是一等公民，CLI 只是载体。
5. **综合判断：可行，建议以「工作区预设生态 + 双向 CLI」的姿态做**，差异化卡位=跨工具通用 + 工作区整体快照 + 脱敏一等公民 + 离线开源无云依赖。最需要盯防的对手：agentsmd（云端 save/restore）、Tencent/teamai-cli（Git 仓库还原，4.7k★）、claude-code-templates（组件级分发心智）。

### 1.2 疑似直接竞品专节

用 10 组中英文关键词主动搜索（portable workspace save/restore、share agent configuration、AGENTS.md template manager、agent workspace snapshot、中文「配置打包复用」等）后判断：**未找到与「save 当前工作区→脱敏打包→create 从包或 Git 预设还原」完全对位的通用 CLI**。实质逼近者四个：

1. **agentsmd**——唯一产品化的「云端 save+restore 工作区配置」，弱在：闭源云依赖、无脱敏、无可分享文件格式、无 Git 预设形态、定位个人多机同步。
2. **Tencent/teamai-cli（4.7k★）**——「Git 仓库还原」最接近，但以团队共享仓库为中心（push→review→pull），没有「把当前工作区反向导出为可分享包」，且面向团队而非个人生态。
3. **OpenClaw bundle 生态**——「完整工作区打包+即装即用」心智成熟，但绑定单一生态。
4. **GitAgent 格式**——「框架无关可分享格式 + 从现有 agent 导出」概念最接近，对象是单 agent 人格定义而非工作区快照。

### 2.2 需求强度与分层警示

- 痛点**反复出现而非一闪而过**：GitHub issue 312 条命中、HN 250+ story、中文教程 2026 全年持续产出。
- 大量用户已动手做半成品（symlink/dotfiles/同步脚本），说明**付费意愿级的痛**，且现有方案不满足。
- **关键警示**：内容型分享（karpathy-skills 213k★）和大而全模板 CLI（claude-code-templates 30.7k★）被验证有海量需求；而小团队的纯工具型 Show HN（Rulegen、Straion、Better Agents CLI 等）普遍 3~10 分、0~3 评论。**痛点真，但纯「配置管理工具」抓不住注意力；赢法接近「内容生态 + CLI」。**

### 2.3 反面证据（官方已缓解的部分）

- 用户级配置（`~/.claude/skills/` 等）已官方支持「配一次全项目生效」；
- plugin marketplace、Vercel skills.sh CLI（支持 18+ agent）、agentskills.io 开放标准（32+ 工具采用）已覆盖**组件级/单件分发**；
- AGENTS.md 已成跨工具事实标准（Cursor/Codex/Gemini/Claude Code 原生识别），`/init` 自动生成指令文件，「从零写配置」成本大幅下降。
- **残余缝隙**：以上全是「按条解决」——没有一个机制能把**调校好的工作区作为整体快照导出（含脱敏）并跨项目/跨机器/跨工具一键复用**。

目标用户画像：同时维护 3 个以上项目、混用多家 agent 工具的重度个人开发者；带新人/小团队的技术 lead（「新同事 clone 下来零 AI 配置」是团队场景最强钩子）。

## 三、技术可行性

### 3.1 六工具配置面盘点（详见调研原始材料，此处摘要）

| 工具 | 指令文件 | 纯文件域（易打包） | 需合并的 JSON/TOML | 凭证/状态（不打包） |
|------|----------|--------------------|--------------------|---------------------|
| ZCode | `AGENTS.md`（用户级+工作区级） | `.zcode/skills/`、`.agents/skills/`、`commands/`、插件目录 | `~/.zcode/cli/config.json`、`<repo>/.zcode/config.json`（MCP/hooks/插件） | `~/.zcode/v2/credentials.json`、memories/rollout/db 等〔本机实查〕 |
| Claude Code | `CLAUDE.md`、`.claude/rules/` | `.claude/skills/`、`commands/`、`agents/` | `.claude/settings.json`、`.mcp.json`、`~/.claude.json` | `~/.claude/.credentials.json`、projects/*/memory/ |
| Codex CLI | `AGENTS.md`（分层发现） | `~/.agents/skills/`、`.agents/skills/` | `~/.codex/config.toml`（MCP/skills/providers） | `~/.codex/auth.json`、history/sessions |
| Cursor | `AGENTS.md`、`.cursor/rules/*.mdc` | rules 目录 | `.cursor/mcp.json`、`~/.cursor/mcp.json` | IDE 登录态；**User Rules 无文件路径（唯一无法文件还原项）** |
| Gemini CLI | `GEMINI.md`（可配 fileName 兼容 AGENTS.md） | `~/.gemini/extensions/`（含 skills/commands/hooks） | `~/.gemini/settings.json`、`.gemini/settings.json` | `~/.gemini/oauth_creds.json`、扩展 `.env` |
| OpenCode | `AGENTS.md`（CLAUDE.md 兜底） | `.opencode/{agents,commands,skills,...}/` | `opencode.json` | 会话数据 |

关键观察：**指令/skill 层已事实收敛**——SKILL.md 与 `.agents/skills` 约定被 ZCode、Codex（及 Claude Code 生态）共享，纯 Markdown 复制即用；波动集中在 JSON/TOML 的键名与层间语义。

### 3.2 脱敏点清单（`save` 必须处理）

- **明文密钥高频位置**：所有 MCP 配置的 `env`（stdio）/`headers`（remote）——横跨 6 种格式的 `mcpServers` 字段；Claude Code `settings.json` 的 `env` 块；Gemini 扩展 `.env` 文件；Cursor/Gemini 的 `${env:VAR}`/`${VAR:-default}` 插值默认值里可能写了真值。
- **整体排除**：各工具凭证文件（credentials.json / auth.json / oauth_creds.json）、会话历史、memory/记忆目录、日志与 SQLite 索引。
- **可借鉴范式**：Gemini 扩展的 `sensitive:true` 进系统 keychain——打包器可输出「占位符 + 需手工配置的环境变量清单」，Claude Code 官方对凭证类变量在 url/headers 中读空，可模拟同样策略。

### 3.3 「Git 仓库即预设」可行性

可行，且**不需要发明私有 schema**：顶层放跨工具共享的 `AGENTS.md`（ZCode/Codex/Cursor/OpenCode 原生识别，Claude Code 可 `@AGENTS.md` 引入）；`skills/` 直接采用 `.agents/skills` 约定；还原时把纯文件域链接/复制到各工具目录，对每家唯一的 JSON/TOML 做**合并写入而非覆盖**（这些文件混着用户自己的其他设置，六家全如此）；MCP 存一份中立声明，按各工具 schema 生成片段，密钥一律写 `${ENV_VAR}` 引用。Windows 无 symlink 权限时退化为复制。

### 3.4 风险

- **格式变动快（最大维护成本）**：Codex 2026-03 移除 prompts 子系统转 skills、2026-05 拒绝 legacy profiles；Claude Code commands 并入 skills；Gemini CLI v0.3.0 settings 从扁平改嵌套；OpenCode 目录单数→复数靠兼容硬扛；Cursor `.cursorrules` 已从文档移除。→ 适配器需要版本化 + 快速跟进机制。
- **跨平台**：三家工具的 managed/system 级路径按 OS 各异；Claude Code plugin link mode 官方声明 Windows 不支持——还原器在 Windows 用复制；用户级路径大体一致（`~` = `%USERPROFILE%`）。

### 3.5 难度评级

| 部分 | 评级 | 理由 |
|------|------|------|
| 纯文件复制（skills/commands/rules/AGENTS.md） | **易** | 全是 Markdown 目录树，约定已收敛，复制即用 |
| 配置合并（约 8 个 JSON/TOML 合并点） | **中** | 均有明确 schema 与优先级，工作量在映射表与冲突策略 |
| 脱敏 | **难** | 密钥散布、无统一标注、误判代价不对称（漏一个字段即泄露），需保守白名单 + 人工确认环节 |

## 四、结论与建议

### 4.1 可行性判断：**可做，但要带着清醒的姿态做**

- **市场维度**：空白成立（无对位产品）但不是无人区——agentsmd 从云端、teamai-cli 从团队 Git、claude-code-templates 从组件级、OpenClaw 从单生态打包，四面包抄。纯「工具能打包」不是护城河。
- **需求维度**：痛点真实（5k+ 赞 issue、30.7k★ 安装器、满地手工方案），但工具型产品在 HN 冷启动普遍失败，**成败变量是内容生态而非 CLI 功能**。
- **技术维度**：可行，核心工作量在脱敏引擎与各家配置合并器；格式变动要求持续维护投入（单人项目的主要长期成本）。

### 4.2 差异化卡位（相对所有已核实竞品）

1. **跨工具通用**：不绑定单一 agent（对比 claude-code-templates、OpenClaw bundle）；
2. **工作区整体快照**：save 的是「你调校好的整套工作区」，不是单组件/单 agent 定义（对比 GitAgent、plugin marketplace）；
3. **脱敏一等公民**：打包即扫描、占位符化、生成环境变量清单（目前仅 claude-handoff 在 session 层做过，工作区配置层无人做）；
4. **双形态分发**：包文件 + Git 仓库即预设，零后端、离线可用（对比 agentsmd 的闭源云）；
5. **预设内容生态**：官方维护精品预设（深度调研工作区、AI 视频制作工作区、代码评审工作区……），用真实内容吸引安装——这是对「Show HN 惨案」的直接解法。

### 4.3 若决定做，建议的验证顺序（非实现细节）

1. 先手工做一个「Git 仓库即预设」的样例仓库 + 一份还原脚本（不写正式 CLI），验证「一键还原出开箱即用工作区」的真实体验与坑；
2. 用自己的两个真实工作区（深度调研、AI 视频制作）作为首批预设，发布 minimal CLI（save 单工具版，先 ZCode 或 Claude Code）；
3. 验证反馈后，再扩脱敏引擎与多工具适配器，每次适配器更新跟随上游版本发布。

### 4.4 待复核事项

- karpathy-skills 的 213k★ 数据增速异常（两处 API 一致但仍建议人工复核）；
- Reddit 原帖互动数据未能直接核实（直连超时）；
- OpenAI developers.openai.com 调研当日整体 403，Codex 的部分路径结论来自第三方转载与通行认知，已逐条标注。

## 2026-09-16 追加章节：claude-code-templates 深度拆解

应用户要求，对调研中识别的最大邻近玩家 [davila7/claude-code-templates](https://github.com/davila7/claude-code-templates) 做专项拆解。来源：GitHub API、raw README、CHANGELOG、aitmpl.com、docs.aitmpl.com（llms.txt 索引 + installation.md + guides/workflows.md + concepts/templates.md），均于 2026-09-16 抓取。

### A. 定位与量级

- GitHub API 已核实：**30,759★ / 3,492 forks / 256 open issues**，创建于 2025-07-04（约 14 个月），MIT 协议，主语言 Python，**调研当日仍有 push**（极活跃）。官网 aitmpl.com。
- 官方文档宣称 **1000+ 组件**：400+ agents、225+ commands、65+ MCP、45+ hooks、60+ settings、14+ templates。
- npm 包 `claude-code-templates`（短别名 `cct`），周下载 **1,736**（2026-09-16 核实）——与 30.7k star 存在量级落差。
- 商业背书：Z.AI、Vercel OSS、Neon、Bright Data、Claude for Open Source 赞助；作者 davila7 有 Buy Me A Coffee。

### B. 产品三层结构

1. **CLI**（`npx claude-code-templates`）：交互式浏览 + 按 flag 安装六类组件（`--agent/--command/--mcp/--setting/--hook/--skill`）。**默认装到当前项目 `.claude/`**（agents/、commands/、mcps/、settings/、hooks/、skills/，MCP 另写根目录 `.mcp.json`），`--directory` 换目标项目；新组件与现有配置**合并**；`--dry-run` 预览、`--yes` 跳确认、`--health-check` 校验。Global Agents 是独立机制，存 `~/.claude-code-templates/agents/`。周边命令：`--analytics`（token 用量面板）、`--chats`（+ `--tunnel` 经 Cloudflare Tunnel 手机看会话）、`--plugins`、`--teams`（多 agent 协作面板）。
2. **Marketplace 网站**（aitmpl.com）：⌘K 搜索、按类浏览、Trending、**Stack Builder**（浏览时点 + 号凑组件栈再一条命令安装）、"Promote your component"（Google Form 提交，非自助上传）。无账号体系、无定价。
3. **后端与基础设施**：Supabase/Neon 做下载追踪，Cloudflare Workers + Discord bot；仓库还有 `cli-rust/`（Rust 重写进行中）、`dashboard/`、`database/`。

### C. 组件来源 = 聚合 + 署名（值得注意的增长模式）

内容并非原创为主，而是从 8+ 个第三方仓库聚合并保留原 license 署名：K-Dense-AI 科学技能（139 个）、anthropics/skills 官方（21）、obra/superpowers（14）、alirezarezvani/claude-skills（36）、wshobson/agents（48）、awesome-claude-code（21 commands）等。贡献走 PR + CONTRIBUTING 规范。**聚合+署名+官网目录**是其增长引擎。

### D. 可复用机制：Workflows 与 Templates（与本项目最接近的部分）

- **Workflows** = 可复用安装清单：YAML（`steps: [{step, type, name}]`）或 12 位 hash（**存浏览器 localStorage，换机/他人不可用**）；分享走 hash URL、GitHub Gist、Git 仓库、npm 包；创建只能靠 aitmpl.com/workflows 拖拽构建器或手写 YAML——**没有「从现有 .claude/ 反向导出成 workflow」的功能**。
- **Templates** = 12 个官方预配置包（语言/框架/工作流/用例四类，如 Python、React+TS、Security First、Full-Stack），支持按 package.json/requirements.txt/go.mod **自动检测**项目类型安装。
- 「分享自定义模板」的官方建议是三条手工路径：`tar -czf` 打包 `.claude/` 和 `.mcp.json`、手写 workflow YAML、把 `.claude/` 提交进 git——**说明文档自己承认反向打包没有产品化**。

### E. 确认无 save/export

README 全部 12 个 flag 逐条核对 + CHANGELOG 全量核查：无 `--save/--export/--extract/--snapshot/--bundle`，无工作区概念。最接近的 1.26.0 "Context download" 只是会话上下文导出（且已被 session sharing 替代过一轮）。**支持范围仅 Claude Code，未提及任何其他 AI 工具。**

### F. 值得注意的信号

1. **星标与使用落差**：30.7k★ vs npm 周下载 1.7k——star 更多反映「内容目录」价值，CLI 本身粘性有限。
2. **迭代放缓**：2025-10~11 月三天一版（1.25.0→1.27.0），2026 年起明显降速（1.28.3 → 1.29.4 间隔约 8 个月，且主要是安全补丁）。
3. **安全事件**：v1.29.4（2026-07-13）修复 Claude Code Studio 的未认证 OS 命令注入 RCE（CVSS 8.8）——**社区配置安装器是真实攻击面**，佐证本项目把「脱敏与安全」当一等公民的必要性。
4. 256 个 open issue + Rust 重写并行——维护成本已经显现。

### G. 对本项目的启示

- **值得借鉴**：聚合+署名的内容来源模式；Stack Builder「凑栈」交互；YAML 清单作为可分享格式（业界心智已被它教育）；官网内容目录作为增长引擎；按项目文件自动检测推荐的 UX。
- **需要避开**：单工具绑定；浏览器端 hash 分享（跨机失效）；冲突/合并策略不做文档化说明。
- **差异化卡位被再次确认**：双向 save（它 14 个月没做，且官方文档承认只能手工 tar）、跨工具还原（它只有 Claude Code）、脱敏（它完全没有）。
- **风险提示**：它加 save 功能的技术门槛不高（组件路径它全知道）；但其团队当前重心在监控分析（analytics/chats/teams）而非工作区复用，短期跟进概率低。
