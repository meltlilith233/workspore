# Workspore CLI — Spec

Status: ready-for-human
Feature: workspore-cli
日期：2026-09-17
来源：产品定义（定稿）、CONTEXT.md、ADR-0001/0002/0003

## Problem Statement

脚手架是每个 AI 重度用户交的隐形税——反复交、难沉淀、带不走。核心用户是频繁开新类型任务（视频创作、深度调研……）的重度 AI 工具用户，他们的具体痛点：

- 每次开新任务都得重搭目录约定、命名规范、流转约定、常用 skills，摩擦大到吃掉开工意愿；
- 打磨出的调校成果随任务结束散落在一次性目录里，下次开同类任务全靠回忆和手抄；
- 换电脑、重装系统要花几小时重配，还总会漏掉当年踩坑才补上的设置；
- 想分享只能整个目录连素材带密钥一起拷，又乱又不安全。

## Solution

一个双向 CLI，两个动作，初始化之后退场：

- **save**——把调校好的工作区固化成带版本的模板。固定的规则逻辑：自动收上下文（指令文件原样）与能力（skills、命令、MCP 声明），外加作者显式选入的文件；脱敏打包（密钥换占位符，家底永不进）；产出 Git 仓库形式的模板，版本即 tag。
- **create**——从模板落出新工作区，落地即巅峰；在实例里留一行出身（来源模板与版本）。

初始化之后工具退场：旧工作区想跟上模板新版本是它里面坐着的 agent 的活，产品不做更新机制。分享就是公开仓库，公开即分享；平台不做。

## User Stories

1. 作为频繁开新类型任务的用户，我想把调校好的工作区固化成带版本的模板，以便调校成果不再随任务结束散落，下次开同类任务不必从零重来。
2. 作为模板作者，我想让 save 自动收走上下文（指令文件原样）和能力（skills、命令、MCP 声明），以便不必逐项手挑，调校的核心成果一键入模板。
3. 作为模板作者，我想让中间地带文件（公共脚本、范本、prompt 库）默认不进模板、由我显式选入，以便模板不被一次性内容污染，什么值得带走由我决定。
4. 作为模板作者，我想让 save 自动脱敏——密钥一律换成占位符、素材和产出等家底永不进模板——以便模板可以放心设为公开仓库。
5. 作为模板作者，我想 save 一次就产出一个新版本（Git tag 自动递增），以便每个版本可追溯、可回退。
6. 作为模板作者，我想在约定级破坏性变更时手动标大版本，以便版本界线反映模板的兼容性。
7. 作为要开新任务的用户，我想用 create 从模板落出全新工作区，以便它一落地就是调校好的状态，我的时间只花在任务本身。
8. 作为新实例里的 agent，我想通过上下文拿到目录、命名、流转的全部约定，以便第一句任务指令就能按规范干活、自己长出结构（模板不搬目录，ADR-0001）。
9. 作为用户，我想让 create 在实例里留一行出身（来源模板与版本），以便将来让 agent 把工作区跟上模板新版本时有据可查。
10. 作为换电脑或重装系统的用户，我想在新机器上装好 CLI 后直接 create 还原工作区，以便几小时重配和漏配踩坑设置成为历史。
11. 作为朋友或协作者，我想拿到一个模板仓库地址就能 create 出同款工作区，自己完成一次性密钥配置后开工，以便分享干净、素材和密钥留在各自本机。
12. 作为陌生人，我想 clone 公开模板仓库就能 create 出开箱即用的工作区，以便他人的调校成果可被任何人复用。
13. 作为混用多个 agent 工具的用户，我想让模板原样保存工作区里已有的各工具指令文件（有哪个存哪个），以便还原后各家工具看到的调校状态与源工作区一致（ADR-0002）。
14. 作为模板作者，我想模板就是标准 Git 仓库，以便 diff、log、分支、PR 等 git 的全部能力直接可用于管理模板。
15. 作为用户，我想 save 的默认行为是确定、离线、可预测的规则逻辑，以便工具行为可审计、不依赖模型可用性。
16. 作为后续维护者，我想让工具在初始化之后彻底退场（无 update、无运行时跟踪），以便产品保持薄，跟进、合并、引导等语义工作留给工作区里的 agent（ADR-0003）。

## Implementation Decisions

- 双向 CLI，只有两个命令：save 与 create；初始化之后工具退场（ADR-0003）。不做实例更新跟踪、冲突合并、首跑引导。分工原则：工具管字节（固化、落地），agent 管语义（整理、合并、引导）。
- 模板内容（ADR-0001）：上下文（指令文件）+ 能力（skills、命令、MCP 声明）+ 作者显式选入的文件；目录骨架一个不带，结构由 agent 读上下文自己长出来。
- 指令文件存储（ADR-0002）：原样存源工作区里存在的所有指令文件，不归一、不生成各工具变体。
- 模板载体：Git 仓库（零后端）；版本 = tag，save 一次自动打递增 tag，大版本手动标（semver 粒度实现期定）。
- 脱敏：规则引擎处理已知密钥位置（MCP 声明的 env/headers、settings 的 env 块、常见密钥文件形态），一律替换为环境变量占位符；凭证文件、会话与记忆数据、日志索引、素材、产出一律排除。策略保守：宁可误拦、人工救回，不可漏放。
- 出身：create 在实例里写一行来源模板与版本的记录，之后工具不再维护它。
- 中间地带文件的显式选入：以工作区内一份选入清单为准，save 只按清单收，清单外的非常规文件不进模板。
- 分发零机制：公开仓库即公开分享；无平台、无目录、无市场。
- save 不接 LLM：默认规则模式（已记录待议）。
- 各 agent 工具的配置格式适配范围（先覆盖哪家、哪些字段）不在本 spec 锁定，属实现期逐工具决策（见 Further Notes）。

## Testing Decisions

- 唯一测试缝：命令行边界（用户已确认）。测试把 CLI 当黑盒：参数进、可观察状态出（文件系统 + git 仓库状态）；进程内调命令层或起子进程均可，但断言只落在外部状态上。
- 不为内部模块（脱敏引擎、git 适配等）开独立测试缝；它们的正确性全部经由命令行缝验证。
- 好测试的标准：只断言外部行为——模板仓库的文件内容、tag 列表、实例的文件与出身行、占位符替换结果；不断言内部结构、不 mock 内部模块。
- fixture：临时目录搭假源工作区（指令文件、能力目录、故意埋的假密钥、选入清单与中间地带文件）+ 假模板仓库；save→create 全链路回归在同一缝上完成。
- 绿地无前例：本 spec 的测试将建立仓库的测试惯例；开发环境为 Windows，断言时注意跨平台路径行为。

## Out of Scope

- 实例跟进模板更新（update 命令、三方合并、冲突裁决）——agent 场景（ADR-0003）
- 首跑引导/开工检查单/冒烟考题——模板作者的上下文内容，非产品机制
- 模板市场/目录/收录等平台功能
- save 接入 LLM（提议选入、语义脱敏、版本叙事）——记录待议，先不接
- 指令文件归一与按工具生成变体（ADR-0002 否决）
- 目录骨架搬运（ADR-0001 否决）
- 用户级全局配置（~/.claude 等）的同步与备份

## Further Notes

- 词汇表见 CONTEXT.md（模板、实例、上下文、能力、家底、出身）；产品定义见 Workspore产品定义.md；决策记录见 docs/adr/0001~0003。
- 工具适配范围建议拆工单时逐个确认，优先覆盖模板作者实际在用的工具。

## Comments

**2026-09-18 实现完成（agent）**：Node ≥ 20、ESM、零运行时依赖；`bin/workspore.js` + `src/`（collect 选入规则 / sanitize 脱敏规则引擎 / save / create / git / glob）。实现期决定（spec 留白处）：

- 首个版本 `v0.1.0`，`--minor` / `--major` 手动抬档，无变化不打新 tag。
- 模板默认落工作区旁 `<名>-template`，`--to` 可指定；模板工作区每次镜像选入结果（清单移除即模板删除，人工救回需回写源工作区）。
- 指令文件覆盖 v1 名单：AGENTS/CLAUDE/GEMINI/.cursorrules/.windsurfrules/.github copilot-instructions/.cursor rules；能力覆盖 .claude/.agents/.zcode 的 skills 与 commands、.mcp.json/.cursor/mcp.json、.claude/.zcode 共享 settings（env 块脱敏）。
- 选入清单为工作区根 `.workspore` 文件（glob 每行一个，# 注释，纯目录名按目录/**理解），清单本身随模板走；凭证与素材形态即使选入也拦截并警告（宁可误拦、人工救回）。
- create 走 git clone（本地路径与 URL 同一机制），默认取最新 semver tag，出身一行写 `.workspore-origin`；实例不继承模板 .git。
- 测试 25 个全绿（`node --test`），全部经命令行黑盒缝，断言只落文件系统与 git 状态；含中文路径用例（Windows）。

**2026-09-18 code-review 修订（agent）**：双轴评审（Standards/Spec）后修正——

- **人工救回此前是死路**：被拦文件无论清单怎么写都进不了模板，手工拷进模板仓库又会被下次 save 镜像删除。现给 `.workspore` 清单加 `!` 前缀强制选入：可救回素材/产出误拦且不被镜像删除；凭证形态连 `!` 也拦（不可漏放）。
- 测试缝收紧：删去两处对 stdout 文本的断言（Testing Decisions 要求断言只落文件系统与 git 状态）。
- 测试计数修正：此前 create.test.js 从 save.test.js import fixture 导致 save 套件双跑，"25 个"实为 15 个用例的重复执行；fixture 移入 helpers 后 15 个全绿。
- 消重：semver 解析/比较/递增抽到 `src/version.js`（save 与 create 共用），tag 列表读取收进 `src/git.js` gitTags；删除未用的 BUCKET_LABEL 与 manifestPatterns 返回值。
- 实现期解读备案（Spec 评审提出）：spec 的「常见密钥文件形态」按「凭证文件…一律排除」实现为整文件拦截，占位符替换只适用于声明文件内的 env/headers；`-m`/无变化不打 tag/create 播报占位符数等超出 spec 字面的小项按「合理 UX/健壮性」保留，均记录于此。
